The ONE Dangerous Bug: Memo Fallback

You said:

if updateV1 fails, fallback to memo instruction instead

This is NOT SAFE for your upgrade store.

Because:

memo ≠ metadata update

So worst case:

User pays

Image + metadata uploaded

Transaction succeeds (memo)

BUT NFT URI never changes

User sees no upgrade → trust broken 💀

This is a silent data integrity failure.

❗ Why This Fallback Is Dangerous

From a blockchain perspective:

Memo instruction always succeeds

updateV1 might fail due to:

wrong authority

delegate mismatch

asset frozen / immutable

invalid newUri

missing collection authority

If fallback executes:

You get a SUCCESS tx that does NOTHING.

That’s worse than failing loudly.

🧠 Correct Behavior for Production

You should HARD FAIL if updateV1 fails.

Because upgrade flow is atomic:

Payment ✔
Image ✔
Metadata ✔
On-chain update ❗ MUST succeed

If last step fails → rollback / refund / retry.

🔧 Recommended Fix

Replace:

try {
  return updateV1Instruction;
} catch (e) {
  return memoInstruction; // ❌ dangerous
}

With:

try {
  return updateV1Instruction;
} catch (e) {
  console.error("Core updateV1 failed:", e);
  throw new Error("METADATA_UPDATE_FAILED");
}

Then surface to UI:

"Upgrade failed on-chain. Payment safe. Please retry."
